# Practice 顶部共享控制区 UI 优化执行方案

日期：2026-09-13  
状态：已实现（`HeaderSettings.tsx` / `PracticePage.tsx` / `App.tsx` / `index.css`），见第 9 节验收清单  
范围：Practice 顶部练习控制、设置分类与临时设置面板

## 1. 目标与需求澄清

将现有 `.practice-header` 的内容移入设置内容所在的共享区域。默认显示曲名、进度、时间、播放按钮、速度及 Score / Library；只有点击 Mode、Hands、Tempo、Input、More 时，才用该分类设置替换默认内容。设置控制区连续 10 秒无操作后自动恢复默认内容，不增加专门的返回按钮。

上一轮评审中“默认显示 More”和“曲目与播放控制始终显示”的建议与原始需求不一致，本文件予以修正：默认状态是练习控制，More 只是一个临时设置分类；设置打开期间，原练习控制内容暂时不可见。分类导航始终可见。

本文件针对该交互的要求优先于旧 UI 方案中相冲突的顶部布局描述。其他工作区布局继续遵循现有设计。

## 2. 页面结构

```text
Practice 顶部
├── 分类导航：Mode | Hands | Tempo | Input | More（始终可见）
└── 共享内容区域（同一时刻只显示一种内容）
    ├── 默认：曲名、Seek、时间、Play/Pause、速度、Score/Library
    └── 临时：当前分类名称及该分类设置
```

- 桌面端优先让导航与共享区并排排列，共享区占据剩余宽度。
- 手机端允许导航和内容分行；导航保留所有分类，必要时仅导航横向滚动。
- 删除原位置重复的练习控制栏，避免两个播放入口同时存在。
- 共享区应在同一断点下预留足够的最小高度，切换时避免谱面及键盘上下跳动；允许文字放大时自然增高，不硬裁剪。
- 设置内容较长时使用现有分页或局部布局，分页按钮不属于返回按钮，可以保留。

## 3. 状态与切换规则

建议用 `activeCategory: null | 'mode' | 'hands' | 'tempo' | 'input' | 'more'` 表达状态，`null` 表示默认练习控制。

| 触发 | 结果 |
| --- | --- |
| 进入 Practice | 默认练习控制；所有分类未展开 |
| 点击分类 | 显示对应设置，分类高亮，启动 10 秒计时 |
| 点击另一分类 | 切换设置，进入该分类第一页，重新计时 |
| 再次点击当前分类 | 立即恢复默认控制 |
| 在设置内操作 | 更新设置并重新计时，保持面板打开 |
| 无操作满 10 秒且无保护条件 | 恢复默认控制，取消分类高亮 |
| 设置打开时按 Escape | 恢复默认控制，必要时将焦点交还原分类按钮 |
| 离开 Practice / 组件卸载 | 清除计时器和事件监听 |

自动恢复仅改变显示内容，不撤销已经生效的设置，也不改变 Score / Library 当前选择。

## 4. 10 秒无操作的精确定义

使用单一常量 `SETTINGS_IDLE_TIMEOUT_MS = 10_000`。计时范围是分类导航、当前设置内容及其关联弹出控件。

- 点击、触摸操作、按键、输入、值变化及分页均重新计时。
- 不将音频播放进度、MIDI 音符、后台状态更新或 React 重渲染视作设置操作，避免面板永不恢复。
- 鼠标单纯停留或细微移动不阻止恢复。上一轮“悬停即暂停”的建议不采用，以免用户把鼠标留在按钮上后无法自动返回。
- 拖动滑块、指针按下未释放、输入法组合输入、关联下拉框/弹出选择器打开期间，暂停恢复；交互结束后重新开始完整的 10 秒。
- 键盘操作进入设置内容后，焦点仍位于设置内容或其关联弹层时暂停恢复；离开后重新计时。分类导航上的焦点不需要阻止恢复，因为导航始终存在。
- 鼠标点击按钮产生的普通焦点不能无限期阻止恢复。计时到期时若待隐藏内容持有焦点，应先将焦点移回对应分类按钮；若焦点已在其他区域，保留原焦点。
- 不假设能够可靠检测屏幕阅读器虚拟光标。通过键盘焦点保护、清晰区域名称和手动无障碍验证降低自动消失的影响。
- 浏览器标签页隐藏时暂停；重新可见后开始完整的 10 秒，避免返回页面瞬间切换。
- 旧计时器必须在分类切换和状态退出时失效，不能关闭后来打开的分类。

不添加倒计时弹窗或阻塞提示。10 秒是正常空闲行为，正在编辑和键盘使用属于明确例外。

## 5. 内容与操作反馈

- 默认内容复用现有练习控制的功能、禁用条件和事件逻辑。
- 当前设置分类通过按钮高亮和简短分类标题识别，避免依赖颜色作为唯一线索。
- More 中保留 Advanced、Diagnostics 入口；Debug 改用清楚的 `Debug mode: On/Off`，并同步 `aria-pressed`。
- 速度显示与 Tempo 设置读取同一状态；动态无障碍名称明确当前倍速及下一步动作，边界行为沿用并准确描述现有逻辑。
- 不显示专门的 Back 按钮。再次点击当前分类和 Escape 提供立即恢复入口，不必等待 10 秒。
- 内容切换可以使用约 120–180ms 的轻微淡入，遵循 `prefers-reduced-motion`；隐藏内容不能继续接收点击或 Tab 焦点。
- 无曲目时仍显示合理的默认空状态及 Library 入口，保留既有设置禁用规则。

## 6. 无障碍语义

本方案允许“全部分类关闭”，保留普通按钮加展开状态的语义更直接，不强制改成 Tabs。

- 导航继续使用 `role="group"` 和明确名称。
- 每个分类按钮具有正确的 `aria-expanded`；面板显示时通过有效的 `aria-controls` 指向设置区域。
- 设置面板使用 `role="region"`，通过分类标题命名；默认控制使用适当的独立可访问名称。
- 默认状态所有分类 `aria-expanded="false"`，不将 More 标成选中。
- 点击分类后焦点保留在触发按钮，Tab 可进入面板；移除现有自动聚焦 Back 的逻辑。
- Escape 只在共享控制区及关联弹层的适当范围处理；弹层自身需要 Escape 关闭时，先尊重该层行为，不抢占其他页面控件的 Escape。
- Score / Library 本轮可以保留现有互斥按钮及 `aria-pressed`。若执行 agent 改为 Tabs，必须同时实现面板关联及完整键盘行为，不能只更换 ARIA 属性。
- 不为持续更新的播放时间添加高频播报。

执行 agent 应沿现有组件调用关系确认播放控制所需数据与回调，可通过组合组件或插槽复用，避免复制一套业务逻辑。不要为了迁移 UI 把局部显示状态无必要地提升到全局 store。

临时隐藏练习控制不得停止播放、重置进度、重新加载歌曲或影响录音、识别与评分生命周期。若组件卸载会触发这些副作用，应先分离业务生命周期与显示组件，再实现内容替换。

保留 Advanced、Diagnostics 原有路由行为；离开页面后不留下恢复计时器。不扩展到音频引擎、评分算法或整个应用导航重构。

## 8. 实施顺序

1. 检查现有组件与样式依赖，确定共享区域的数据和回调来源。
2. 接入默认练习控制，完成分类替换，移除重复栏和 Back 控件及相关焦点逻辑。
3. 实现单一空闲计时机制、交互保护、焦点交还与清理。
4. 调整响应式、分类高亮、可访问名称和轻量过渡。
5. 运行与修改有关的现有检查，为计时与焦点这种行为逻辑补充必要测试，并进行桌面及手机视觉验收。
