## 1. 目标与验收原则

让用户能够直接判断：接下来弹哪些键、何时弹、哪些键仍未完成，以及自己的输入是否得到确认。视觉精修服务于这些信息，而不是仅增加运动和光效。

本方案以行为、几何位置和浏览器实测验收。现有测试通过不代表指引效果已达标。文中的代码问题已通过静态审查确认；实际显示误差、交互延迟和视觉效果仍需测量。

## 3. 保留的基础与边界

- 保留播放引擎的单一权威时钟；动画不得产生独立演奏时间或触发参考音符。
- 保留共用键位几何；进一步统一实际绘图宽度、边框和滚动偏移。
- 正常播放的时间映射保持：音符起音前缘在参考开始时刻到达命中线。
- 保持单手筛选现有回退语义：无匹配手部数据时回退到整曲；显示与播放必须一致。
- 不以本方案重写评分算法、MIDI 数据或谱面排版。若审查发现引擎暂停时刻影响指引，先记录复现证据，再单独界定修复范围。
- 不把参考音符自动亮起称为“弹对”；确认反馈必须来自实际输入或既有匹配结果。
- 不在播放中按密度突然改变预告窗口，否则会造成位置或速度跳变。

## 4. 目标行为与状态定义

| 场景 | 指引层 | 琴键与反馈 |
| --- | --- | --- |
| 未加载曲目 | 不显示落键区域 | 保留可操作键盘 |
| 已加载、尚未播放 | 由显示模式决定预览；无自动确认动画 | 可提示首组目标，不显示已弹对 |
| 倒计时 | 显示即将进入的首组，明确倒计时状态 | 目标提示与倒计时同步 |
| Listen | 按参考时间预告与落键 | 表达示范音，不显示学习者成功反馈 |
| Play Along | 预告下一组、当前起音及持续音 | 分离目标、用户按下、匹配确认三种语义 |
| Wait 等待输入 | 以 `waitingForMidi` 为剩余目标来源，在命中区固定显示目标 | 持续突出未完成键；逐个输入后更新剩余集合 |
| 普通暂停 | 保留冻结画面与暂停状态 | 不把暂停误显示成完成或新的落键 |
| Stop / 曲目结束 | 清理临时反馈；结束后按模式回到预览或隐藏 | 不残留上一曲目标和成功光效 |
| 无动画偏好 | 使用按起音分组的静态目标队列 | 同组和弦保持同层，不使用脉冲或拖尾 |

建议提供 Guidance、Subtle、Off 三种显示模式：完整预告、仅当前与下一组、关闭。初始采用 Guidance；模式名称、默认值和是否持久化在 P1 实施时记录。仅在用户切换模式时允许区域高度改变，播放/暂停不应使琴键跳动。

## 5. 实现设计

### 5.1 共用目标数据

将单手筛选提取为可复用的纯函数，让播放、评分、预告和参考琴键消费一致结果。建立指引所需的派生数据：当前持续音、下一起音组、等待剩余键和可见时间窗口。

起音分组保留原始事件标识；若使用容差合并，必须记录阈值并验证不会把琶音合并为和弦。同音重复事件不能仅以 MIDI 音高作为唯一标识。Wait 的剩余目标以 store 为准，不另建竞争性的等待状态。

### 5.2 连续布局

说明和状态摘要置于区域顶部，Canvas 底部紧贴琴键顶部；命中线及 NOW 标识放在实际落点。两者共用内容宽度、音域与横向偏移，避免边框造成缩放差异。检查整个区域的 sticky 归属和父容器高度，确保页面滚动时两者不会分离。

优先维持五线谱可读空间与键盘操作高度。增大预告高度前，验证桌面短视口和平板布局；不得仅靠继续叠加面板改善预告。

### 5.3 时间与音符表现

- 稳定预告时间窗口；明确窗口单位是参考时间。调整播放倍率后的真实预告秒数应正确解释，不能误标为固定真实秒数。
- 短音符增加可辨认的起音标记；扩大视觉标记不得改变真实起音位置或暗示更长持续时间。
- 同起音和弦保持相同高度；完整音名优先放在顶部目标摘要，窄音条不强塞文字。
- 高亮下一起音组，减弱远期音符；空段落显示适当静态状态，不留下无说明的发光空面板。

### 5.4 视觉精修与输入反馈

采用圆角音条、浅渐变、顶部淡入和细亮边。光晕集中在即将落键及当前落点，不在整块背景持续发光。目标琴键顶部与音条使用同一视觉标识。

区分参考目标、实际按下和匹配结果。匹配结果应关联事件与发生时间，避免同一结果在每帧重复触发；Seek、Stop、换曲时清理过期反馈。若现有匹配数据不足以可靠区分结果，先提供“收到输入”反馈，不伪装为正确判定。

不增加遮挡目标的粒子或大范围拖尾。颜色之外保留轮廓、位置或文字线索；无动画模式保留同等目标信息。

### 5.5 绘制性能

仅在实际尺寸或 DPR 变化时重设 Canvas 缓冲区。缓存可复用几何与主题颜色，并为变化设置失效条件。对长曲按有序起音定位窗口，同时保留跨入窗口的持续音。以性能记录决定是否进一步优化，不预先声称卡顿已被解决。
