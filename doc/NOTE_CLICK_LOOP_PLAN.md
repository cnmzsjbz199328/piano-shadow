> 版本：v1.0  
> 制定日期：2026-09-12  
> 状态：已实施；自动化验收通过，真实音频听音未验证
> 功能编号：NCL（Note Click Loop）  
> 范围：五线谱符尾简化、音符选择、区间循环及必要的播放联动。  
> 本文是后续实施与审查的跟踪依据；勾选任务须附验证证据，不能仅依据代码已编写。

## 1. 用户需求与范围

用户希望减少当前音符尾部对阅读的干扰，参考所附乐谱的简洁连梁方式；点击一个音符后，10 秒内点击另一个音符即可在两者之间循环，否则第一次点击自动失效；循环中点击第三个音符恢复全局播放。

本功能交付包括：

- 按节拍连梁的清晰五线谱显示。
- 第一点等待、超时取消、第二点建立循环、第三点退出的完整交互。
- 循环状态、端点和范围的视觉反馈。
- 与暂停、恢复、变速、进度条、换曲及懒加载联动。
- 循环音频边界和异步任务清理的验证。

不包含：音符编辑、导出、录音转谱、完整制谱引擎、多段循环、循环收藏与持久化。逐轮评分不是用户此次明确要求，是否纳入由第 11 节跟踪，不能默认为已支持。

## 4. 交互状态机

业务状态只有三种；播放状态继续沿用已有 transport 状态，避免把暂停误认为取消循环。

| 当前状态 | 事件 | 下一状态 | 副作用 |
| --- | --- | --- | --- |
| 空闲 | 点击有效音符 X | 等待第二点 | 保存 X 与 deadline，显示待选标记 |
| 等待第二点 | 在期限内点击不同起音位置 Y | 循环中 | 计算 A/B，激活播放引擎，从 A 播放 |
| 等待第二点 | 点击原选择单位或相同起音位置 | 等待第二点 | 不刷新 deadline，可显示简短提示 |
| 等待第二点 | 超过期限 | 空闲 | 清除标记与计时资源 |
| 等待第二点 | 超时后点击 Y | 等待第二点 | 先废弃旧点，再以 Y 开始新期限 |
| 循环中 | 点击任一端点 | 循环中 | 不处理 |
| 循环中 | 点击不同音符 Z | 空闲 | 清除循环，保持播放位置和播放/暂停状态；Z 不同时成为新首点 |
| 任意 | 换曲、清空曲目、销毁会话 | 空闲 | 清除选择、计时器、引擎循环及旧回调 |

计时实现要求：使用单调时间与绝对 deadline；定时器只负责触发清理，不承担真值判断。每次点击重新比较 deadline，避免后台标签页定时器节流导致超时点仍有效。规定 `elapsed <= 10000` 有效，`elapsed > 10000` 失效；同一边界的计时回调不得提前清除合法选择。定时器必须携带会话/选择版本，旧回调不能清除新选择。

## 5. 选择单位与循环时间

### 5.1 音符映射

- 渲染模型为每个可点击音符/和弦保存稳定标识、源 `NoteEvent.id[]`、显示位置与原始起止时间。
- 标识来自曲目与源音符，不使用 SVG DOM 顺序或屏幕坐标。
- 和弦符头共享选择身份。两谱表上同一量化起音位置按同一时间锚点处理，不能互相构成第二点或“第三点”。
- 展示量化不修改 `song.notes`。源时间映射在建模时建立，不能使用量化后的时长代替真实音频边界。
- 时间锚点分组与当前和弦分组保持一致；分组容差须命名并测试，不能另写一套隐含规则。

### 5.2 区间定义

设按时间排序后的两个选择为 A、B：

- `startRef`：A 代表的源音符最早起音。
- `endRef`：B 代表的源音符最晚结束，限制在有效曲目时长内。
- 区间采用 `[startRef, endRef)`；B 本身应完整播放。
- 在该时间范围起音的当前练习声部音符都参与播放，不只播放被点击的两颗音符。
- B 若为长音，其延音期间其他起音也属于该区间；这是“包含 B 完整时值”的结果，需在验收样例中展示。
- A 之前起音、持续到 A 之后的音符首版不补奏；区间内起音但超过终点的音符在边界释放。
- 区间必须有限、合法且 `startRef < endRef`；非法区间保持待选或返回明确提示，不能让引擎进入零时长循环。

### 5.3 控件联动

| 操作 | 建议行为 |
| --- | --- |
| 暂停/继续 | 保留 A/B，继续当前区间位置；10 秒等待仍计时 |
| 第二点在暂停或停止时成立 | 主动从 A 开始循环；仍遵守现有音频启动守卫 |
| 循环中重播 | 回 A；每轮回跳不重复 count-in |
| Stop | 停止播放并清除选择与循环，沿用全局归零语义 |
| 变速 | 保持参考时间区间，重新计算音频调度 |
| 拖进度条到区间内 | 保留循环并定位；暂停时仍保持暂停 |
| 拖进度条到区间外 | 清除循环并定位；不擅自开始播放 |
| 待选时拖进度条 | 清除未完成选择，执行定位 |
| 切换乐谱/曲库界面 | 清除待选点；已建立循环继续播放 |
| 换曲、清空曲目、切换练习声部 | 清除选择和循环，沿用现有重载规则 |
| 开始音频识别 | 清除选择和循环，沿用现有播放互斥守卫 |

## 6. 乐谱显示与操作反馈

### 6.1 连梁

- 保留符干和必要的独立符尾；连续八分、十六分音符按节拍生成符梁。
- 简单拍按拍分组，复合拍按相应分组；休止符、小节边界和不兼容时值中断连梁。
- 不跨谱表或小节强行连接，不把不规则节奏伪装成完整准确制谱。
- 先检查项目安装的 VexFlow API 与类型，验证生成梁和符干方向的调用顺序；不要仅依赖默认 `autoBeam` 的未知分组结果。
- 当前仅近似处理节奏和初始拍号/速度的限制继续保留；变拍、变速图谱的全面准确制谱不属于本次扩展。

### 6.2 反馈与命中

- 待选点使用轮廓和“已选起点，请在 10 秒内选择另一音符”提示；逆序选择完成后再按时间分配 A/B。
- 循环端点显示 A/B，区间采用低透明度背景或细线；跨行时分别绘制可见片段。
- 播放中仅突出当前符头，避免整段共享符梁被染色；A/B 标记不被播放高亮覆盖。
- 符头周围设置适度扩大的透明命中区；密集音符重叠时按最近符头确定，不能由 DOM 覆盖顺序随机决定。
- 触摸滑动超过阈值不算点击。提供键盘聚焦、Enter/Space 选择及可读状态提示；宿主不能继续只用阻断交互语义的 `role="img"`。
- 等待第二点时暂停自动跟随滚动，允许用户找到另一谱行；成立或超时后恢复跟随。
- 新懒加载谱行与宽度变化后的重绘必须重新应用业务状态，但不得每次播放 tick 重建整个 SVG。

## 8. 播放引擎的关键约束

- 提供等价于 `setLoopRange(range)`、`clearLoopRange()` 的接口；界面不能自己轮询 `currentTime` 然后调用 seek 模拟循环。
- Tone.Transport 仍为唯一播放时钟。选择的 10 秒计时仅用于 UI 交互，不驱动音乐。
- `setLoopRange` 与“从 A 开始”需有明确原子顺序，不能出现 UI 已循环、引擎仍播放全曲的半完成状态。音频启动失败时撤销激活状态并展示已有错误反馈。
- 具体采用 Transport 原生循环或重新排程，须先验证与现有 `timeMapping` 的兼容性。不要直接复用曲尾的 `setTimeout(0)` 结束逻辑来做精确循环。
- 边界按音频调度时间安排释放和下一轮起音，不按 JS 回调到达的时间判断“已经到终点”；验证 lookahead 不造成提前回跳。
- 只释放 reference 所有权的音色，不能截断用户正在弹奏的键盘/MIDI 声音。
- 每轮生成新调度版本，旧 Tone.Draw 音符结束回调不能熄灭新一轮同音高高亮。
- 循环回跳不触发整曲 `onEnded`，不结束 attempt、不生成结果页。退出循环后仍应恢复自然曲尾事件。
- pause、seek、变速、清除循环、load、dispose 均须清理或重排音符、节拍器、边界事件与异步播放请求。
- 不累积每轮事件，不以轮数增加数组或计时器；循环多轮后事件数量应保持有界。
