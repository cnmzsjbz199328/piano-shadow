## 1. 目标与设计决策

将 Practice 页面分散的设置入口集中到 `nav.app-nav`。页眉采用固定高度、互斥的共享设置内容区，打开、切换和关闭设置均不挤压曲目区域、乐谱或键盘。

用户确认的方向是：缩短标签、减少设置入口分散、设置闲置时不占据主要内容空间，并考虑多尺寸设备。本文将该方向细化为可实施方案；尺寸和动画数值属于初始设计参数，可在验收证据支持下调整并记录。

| 编号 | 决策 | 验收要点 |
| --- | --- | --- |
| H-01 | 设置统一进入页眉 | 移除曲目下方的 Practice settings 折叠区及嵌套设置入口 |
| H-02 | 同时最多打开一个类别 | 切换类别替换共享内容，不叠加面板 |
| H-03 | 页眉在同一布局模式下高度固定 | 展开、切换、关闭及动画中不增加页面高度 |
| H-04 | 宽屏保留标签，共用内容区 | 标签位置稳定，可直接切换类别 |
| H-05 | 中小屏内容接管标签区域 | 品牌、返回按钮、类别名称保持可见 |
| H-06 | 翻转仅用于共享内容区 | 品牌、桌面标签和主工作区不随设置翻转 |
| H-07 | 设置、曲目操作、演奏反馈分开 | 播放与练习按钮留在曲目区；实时反馈不放入设备设置 |
| H-08 | 保持业务行为 | 不改变播放、识别、评分、设备连接和现有设置禁用规则 |

与 [UI_OPTIMIZATION_PLAN.md](UI_OPTIMIZATION_PLAN.md) 的关系：本计划细化并更新设置布局；其中速度设置移入页眉“节奏”，取代旧文档将速度集中在曲目工具栏的安排。既有 Score / Library 翻转与键盘 Dock 稳定性的约束继续适用。

## 3. 范围与信息架构

### 3.1 设置分类

| 标签 | 内容 | 默认状态表达 |
| --- | --- | --- |
| 模式 | 跟拍、等音、试听，对应现有 play-along / wait / listen | 选中项清晰可辨 |
| 声部 | 双手、左手、右手 | 选中项清晰可辨 |
| 节奏 | 速度百分比及增减、预备拍、节拍器 | 当前数值和开关状态 |
| 输入 | MIDI 设备选择、连接状态、连接操作 | 精简状态点及可访问状态文字 |
| 更多 | 高级设置、识别诊断、Debug panel 开关 | 保留现有入口及路由行为 |

表中中文为设计语义。实施时遵循产品现有语言策略；若界面继续使用英文，短标签统一为 Mode / Hands / Tempo / Input / More。避免像现有模式选项一样把中英文完整描述同时堆在一行。帮助描述通过可用键盘和触屏访问的说明入口呈现，不依赖 hover。

“更多”也使用同一个共享区域，移除本页重复的齿轮设置入口。高级设置及识别诊断继续进入现有页面，不将完整诊断工具移入页眉。

### 3.2 留在主内容的元素

- 曲名、播放/暂停、停止、重新开始、进度、开始/结束练习。
- Score / Library 工作区切换。
- 预备拍进行中、等待音符等练习运行状态。
- 实时演奏反馈：从原嵌套设置区迁出，复用或整理练习反馈区域；避免重复显示已有反馈。其位置和可见性应在阶段一明确，不得因迁移而丢失功能，也不得由设置开关控制其高度。

### 3.3 不在本轮范围

- 播放引擎、音符识别、匹配和评分算法调整。
- 乐谱渲染优化、曲库重构、完整高级设置页面改版。
- 新的输入方式、国际化框架、部署或发布。

## 4. 布局与响应式规则

### 4.1 宽屏：标签常驻，内容共用

```text
收起：♬  模式  声部  节奏  输入  更多
打开：♬  模式  声部  节奏  输入  更多 │ 跟拍  等音  试听  收起
```

分类标签靠左集中排列，内容区使用剩余宽度。闲置时不显示空面板边框或背景块。活动类别采用轻量选中样式；主播放按钮继续拥有更高视觉优先级。

### 4.2 中小屏：内容替换标签

```text
收起：♬  模式  声部  节奏  输入  更多
打开：♬  ← 节奏  速度 − 100% +  下一项 ›
次页：♬  ← 节奏  ‹ 上一项  预备拍 开/关
```

- 打开设置后品牌不动；返回按钮固定在设置区起始位置，返回类别标签。
- 中屏优先展示完整类别；放不下时沿用紧凑分页。
- 手机“节奏”按速度、预备拍、节拍器划分小页；提供可见前后切换按钮和页序信息，边界按钮不可用或隐藏时不得使内容跳位。
- “输入”和“更多”内容同样按实际宽度分页或精简，每个功能必须有明确可见的到达路径。
- 手势滑动可以作为补充，不能成为唯一操作方式。
- 最窄屏默认分类区如无法容纳五个标签，允许仅分类区横向滚动，显示边缘提示；品牌保持固定，聚焦标签自动进入可视范围。不允许整页横向滚动。

### 4.3 初始尺寸

| 可用宽度 | 布局模式 | 页眉高度建议 |
| --- | --- | --- |
| ≥1100px | 常驻标签 + 共享内容 | 56px |
| 700–1099px | 内容接管标签区 | 60px |
| <700px | 内容接管 + 必要分页 | 64px |

以页眉实际可用宽度为依据，不能只按设备名称判断。触控目标至少约 44×44px；必要时触屏布局使用 64px 高度。调整断点需记录原因和截图，不能通过缩小字号、压缩点击区域或允许设置换行解决溢出。

设备长名称省略显示，但可访问名称保留全文。设备选择列表允许使用锚定浮层或原生选择器：这属于选项选择，并非把整个设置面板恢复为向下展开。浮层限制在视口内，可内部滚动，不参与页面高度计算。连接错误在行内给出短状态，通过明确入口查看完整详情；不插入撑高页眉的长段文字。

跨断点或旋转屏幕时保留当前类别和已修改的业务值，将子页调整到有效范围；不重新连接设备、不重启播放。

## 5. 交互、动画与可访问性

### 5.1 状态转换

| 当前状态 | 触发 | 结果 |
| --- | --- | --- |
| 收起 | 点击类别 | 打开对应类别，子页从首项开始 |
| 宽屏已打开 | 点击其他类别 | 共享区替换内容，其他位置不变 |
| 宽屏已打开 | 再次点击当前类别 | 收起 |
| 已打开 | 收起、返回或 Escape | 回到分类入口，焦点返回触发标签 |
| 已打开 | 修改设置 | 即时生效并保持展开；不新增保存步骤 |
| 已打开 | 点击主内容 | 不自动收起，不影响练习操作 |
| 选项浮层已打开 | Escape / 点击浮层外部 | 先关闭浮层；Escape 不同时关闭两层 |
| 任意设置状态 | 离开练习路由 | 清除临时展开状态，保留原有业务状态策略 |

Practice 页眉适用于 `/` 和 `/practice`。其他页面只展示适用的全局入口，不挂载失去上下文的练习设置；保留既有品牌返回主页能力。

### 5.2 动画

- 共享内容区使用约 160–220ms 的轻微翻转；内容完成切换前后容器尺寸一致。
- 中小屏、减少动态效果模式及不支持所需 transform 的环境直接切换或短淡入。
- 翻转面通过重叠布局或等效方式承载，不让新旧面同时参与高度计算。
- 快速连续点击采用“最新选择生效”，取消或合并先前过渡；不能出现双面可操作、停在半面或永久锁定。
- 不复用主工作区的翻转状态，不触发其焦点移动和滚动。

### 5.3 键盘与状态可见性

- 分类采用按钮与受控区域语义，使用 aria-expanded / aria-controls；设置表单区域不套用只适合菜单项的 menu 语义。
- 控件具备完整名称、焦点样式，状态不只通过颜色表达。
- 内容接管导致触发标签隐藏时，将焦点移到返回按钮或明确的面板起点；宽屏标签仍可见时不强制抢走焦点。
- 隐藏面从 Tab 顺序和辅助技术树移除。不要在仍持有焦点的元素上直接隐藏而不迁移焦点。
- 关闭、翻转、跨断点后的焦点处理不得滚动主工作区。
- 不禁用浏览器缩放；验证 200% 缩放下所有设置可达。

## 6. 实施建议与行为保护

建议新增独立的页眉设置组件，例如 `src/components/settings/HeaderSettings.tsx`，由 `App.tsx` 根据路由挂载。分类、小页及动画为临时 UI 状态；模式、声部、速度、设备状态继续读取现有 store，不创建第二套业务状态。

| 文件/区域 | 预期改动 |
| --- | --- |
| `src/App.tsx` | 接入统一页眉设置栏和路由适用性判断 |
| 新增设置组件 | 共享容器、分类内容、紧凑分页、焦点及互斥状态 |
| `TransportControls.tsx` | 移除原 details 设置结构及迁出后的无用依赖；保留曲目操作和运行状态 |
| `MidiDevicePanel.tsx` 或新紧凑设备组件 | 复用业务动作，提供行内设备布局；如旧面板仍被其他页面使用则保留其兼容性 |
| `OverflowMenu.tsx` | 先检查其他引用，再决定保留或清理；不能因替换首页入口误删其他页面功能 |
| `src/index.css` | 页眉固定高度、共享面、响应式规则、减少动态效果；清理确认无引用的旧样式 |
| 现有练习反馈区域 | 安置从设置迁出的 LiveFeedback，并说明与已有反馈的关系 |

迁移前记录并保护现有约束：模式在练习运行或识别活动时禁用；声部在练习运行时禁用；速度遵循现有上下限和步长；其他开关与连接行为保持原有语义。页眉关闭或切换类别不得重置设置、停止设备或清空反馈。

无曲目时沿用原有能力边界：曲目相关类别显示明确不可用状态，输入与更多可用；不得通过新页眉绕过旧控件的业务限制。

开始实施前检查工作树和适用的仓库说明。制定本文时工作树已有 `ScoreView.tsx` 修改和未跟踪的 `doc/SCORE_LAZY_RENDER_PLAN.md`；这些属于其他工作，不能覆盖或顺带提交。实际实施时以当时工作树为准。

### 8.3 检查方式

- 执行 `npm run typecheck`、`npm run lint`、`npm run build`。
- 使用现有 Vitest / Testing Library 为互斥切换、隐藏内容不可聚焦、紧凑返回及业务禁用约束补充有意义的交互测试，并运行受影响的现有测试。
- 使用现有 Playwright 配置验证页眉操作不移动主内容及核心练习流程；按仓库实际测试文件选择命令，必要时运行 `npm run test:e2e`。
- 不为单纯颜色、间距或组件内部状态逐项编写镜像测试。自动检查不能取代宽窄屏视觉审查和真实焦点检查。
- 若缺少真实 MIDI 硬件，可模拟设备状态验证界面，但必须记录真实设备连接仍未验证，不得标为已通过。
