# UI 设计审查：播放控件与导航选中状态

> 状态：待审查
>
> 范围：本轮只讨论播放控件图标和左侧导航选中状态。Library 列表另列为后续设计议题。

## 1. 审查结论

当前界面的主要问题不是功能缺失，而是两个交互状态依赖了平台默认的视觉表现：

1. Play/Pause 使用 Unicode 字符作为图标，在 Apple 设备上可能出现字体、基线、大小和形状差异。
2. 左侧选中标签只有深色背景和一条底部强调线，在渐变背景上层次不足，无法形成成熟产品应有的明确选中状态。
3. Library 列表采用逐行卡片和并列操作按钮，功能完整但层级、密度和操作语义仍有明显的草稿感。

建议分别采用：

- 本地内联 SVG 图标系统；
- 半透明激活胶囊、短强调线和轻微浮起效果。
- 单一列表容器、平面列表行和明确的主次操作层级。

## 2. 问题一：Play/Pause 图标一致性

### 当前实现

播放按钮目前使用 Unicode 字符：

```tsx
<span aria-hidden>{playing ? '\\u23f8' : '\\u25b6'}</span>
```

对应位置：`src/components/transport/TransportControls.tsx` 的播放按钮。

### 现象与风险

- Unicode 图标由系统字体或字体回退机制渲染；
- Safari、Chrome、macOS 和 iOS 可能选择不同字形；
- Play 三角形和 Pause 双竖线的视觉重量不一致；
- 图标的垂直基线可能不同；
- 字体回退时存在出现 Emoji 风格图标的风险；
- `Play` 与 `Pause` 文案长度不同，可能使按钮宽度发生变化。

### 设计目标

- 不依赖系统字体；
- 在 Apple、Windows 和 Android 上保持相同形状和尺寸；
- Play 与 Pause 使用相同的图标盒和视觉重量；
- 状态切换时按钮不发生明显跳动；
- 保留文字和无障碍名称，不让图标承担唯一语义。

### 建议方案

使用项目内的内联 SVG 图标，不引入外部图标字体或远程资源。

统一规范：

- `viewBox="0 0 24 24"`；
- 显示尺寸约 `18px × 18px`；
- 使用 `fill="currentColor"`；
- 图标元素设置 `aria-hidden="true"`；
- Play 使用实心三角形；
- Pause 使用两个宽度一致、略带圆角的竖条；
- 播放按钮设置固定宽度或合理的 `min-width`。

建议结构：

```text
[  ▶  Play  ]
[  ❚❚ Pause ]
```

这里的图形应由 SVG 提供，而不是由文字字符提供。

### 验收标准

- 在 Safari macOS、Safari iOS、Chrome macOS 和 Chrome Windows 中，Play/Pause 图标尺寸和位置一致；
- 切换 Play/Pause 时按钮左边缘和整体位置不跳动；
- 图标颜色始终继承按钮颜色；
- 屏幕阅读器仍然读出明确的 Play 或 Pause 操作名称；
- 不新增外部图标字体依赖。

## 3. 问题二：左侧导航选中状态

### 当前实现

当前选中状态通过 `aria-expanded="true"` 控制：

```css
.header-settings__category[aria-expanded='true'] {
  background: var(--bg-elevated-2);
  color: var(--text);
  box-shadow: inset 0 -2px 0 var(--accent);
}
```

对应位置：`src/index.css` 中的 `.header-settings__category` 样式。

### 现象与风险

- 选中标签与普通标签之间主要只有颜色和底线差异；
- 底线贯穿整个标签宽度，视觉上比较机械；
- 深色背景块在当前渐变背景上缺少精细层次；
- 选中标签没有“浮起”或“当前工作区入口”的感觉；
- 用户需要依靠较小的底线来确认当前所在类别。

### 设计目标

- 让当前类别在一眼扫过时立即可识别；
- 保持左侧导航作为一级导航，而不是看起来像普通按钮；
- 与渐变背景协调，不让所有标签都变成高亮块；
- 保持现有 44px 点击区域和键盘焦点体验；
- 激活状态、悬停状态和焦点状态彼此可区分。

### 建议方案

采用“激活胶囊 + 短强调线”的状态设计：

- 选中项使用半透明深色背景，例如 `rgba(18, 20, 26, 0.82)`；
- 选中文字使用纯白或高亮文本色；
- 增加非常轻的顶部高光或细边框；
- 底部强调线缩短为左右留出空间的 `3px` 蓝色指示条；
- 增加轻微阴影，但避免明显浮夸的发光效果；
- 普通标签只保留文字和低强度悬停背景。

建议视觉关系：

```text
Mode   [ Hands ]   Tempo   Input   More
        └── 蓝色短强调线 ──┘
```

推荐状态层级：

| 状态 | 背景 | 文字 | 其他提示 |
| --- | --- | --- | --- |
| 默认 | 透明 | 中灰 | 无 |
| 悬停 | 低透明度浅色或深色背景 | 高亮灰 | 无 |
| 选中 | 半透明深色胶囊 | 白色 | 蓝色短强调线、轻微阴影 |
| 键盘焦点 | 继承当前状态 | 继承当前状态 | 清晰 focus ring |

### 验收标准

- 当前类别在不阅读文字的情况下也能快速识别；
- 选中状态在渐变背景的不同明度区域都清晰；
- 普通、悬停、选中、键盘焦点四种状态能够区分；
- 标签仍保持现有点击区域，不因视觉改造变小；
- 不使用过强阴影或高饱和色块破坏导航的整体克制感。

## 4. 建议实施顺序

1. 先引入本地 SVG Play/Pause 图标，并固定播放按钮尺寸；
2. 再调整导航选中状态；
3. 在 Safari macOS、Safari iOS 模拟尺寸和 Chrome 中进行视觉检查；
4. 最后检查键盘导航、`:focus-visible` 和屏幕阅读器名称。

## 5. 问题三：Library 列表的产品成熟度

### 当前实现

每首歌曲当前是一张独立的 `.song-row`，包含：

- 歌曲名称；
- 时长和音符数量；
- `Practice`；
- `Export`；
- `Delete`。

相关组件为 `src/components/practice/SongLibrary.tsx`，基础样式位于 `src/index.css` 的 `.song-list` 和 `.song-row`。

### 现象与问题

- 每一行都有完整边框、圆角和独立背景，视觉上像多个临时卡片；
- 三个操作按钮同时出现，主次关系不够明确；
- `Export` 和 `Delete` 与 `Practice` 的视觉权重没有充分拉开；
- 标题、元数据和当前状态之间的信息层级较弱；
- 行内水平留白较大，但没有形成稳定的扫描节奏；
- 列表缺少成熟产品常见的悬停、当前项和操作入口反馈。

当前实现适合验证功能，但还不像一个经过完整产品化设计的音乐库。

### 设计目标

- 让用户先识别歌曲，再理解歌曲状态，最后执行操作；
- 将 `Practice` 明确为唯一主要操作；
- 将导出和删除收纳到次级操作中，尤其降低删除的视觉侵入性；
- 提升列表的可扫描性和信息密度；
- 保留当前歌曲的明确状态；
- 桌面端和移动端都保持自然的操作布局。

### 推荐方向：单一列表容器 + 平面列表行

建议保留一个整体列表容器，行与行之间使用细分隔线，不再让每一行都像独立卡片：

```text
Library                                      Import MIDI

┌────────────────────────────────────────────────────┐
│ ♫  Für Elise — 致爱丽丝                      ⋯     │
│    2:54 · 1,044 notes                 Practice     │
├────────────────────────────────────────────────────┤
│ ♫  DJ Okawari - Flower Dance                ⋯     │
│    5:23 · 2,381 notes                 Practice     │
└────────────────────────────────────────────────────┘
```

建议拆成三个稳定区域：

1. 左侧身份区域：统一的音乐符号或小型封面占位；
2. 中间信息区域：标题、时长、音符数，以及可选的最近练习时间；
3. 右侧操作区域：`Practice` 和更多操作入口。

### 操作层级

推荐从当前的并列按钮改为：

```text
Practice  >  More (…)  >  Export / Delete
```

- `Practice` 使用主按钮样式；
- `Export` 放入更多菜单，或使用低强调度图标按钮；
- `Delete` 放入更多菜单，并继续保留确认提示；
- 更多按钮使用明确的 `aria-label`，例如 `More actions for Für Elise`；
- 如果保留桌面端文字操作，也应将 Export 变为 quiet 操作，将 Delete 变为危险色但不使用高饱和填充。

### 行状态

| 状态 | 建议表现 |
| --- | --- |
| 默认 | 透明或极低对比度背景，底部细分隔线 |
| 悬停 | 轻微背景变化，显示更多操作入口 |
| 当前歌曲 | 左侧 3px 强调条、浅色背景、`Current` 状态标记 |
| 键盘焦点 | 清晰的 focus ring，不仅依赖背景变化 |
| 删除确认 | 继续使用确认对话框，避免误删 |

当前歌曲不建议使用整行高饱和蓝色填充。左侧强调条配合轻微背景色，能更克制地表达“当前正在练习”。

### 排版与间距

- 标题使用 `15–16px` 半粗字体；
- 元数据使用 `12–13px`，颜色低于标题但仍保持可读；
- 标题与元数据间距约 `4–6px`；
- 行内垂直间距约 `12–16px`；
- 行之间使用 `1px` 分隔线，而不是较大的卡片间距；
- 标题过长继续使用省略号，并保留完整 `title` 或可访问名称。

### 响应式行为

桌面端：

- 标题和元数据占据主要空间；
- `Practice` 保留在右侧；
- 更多操作固定在最右侧。

移动端：

- 标题和元数据保持左侧纵向排列；
- `Practice` 作为右侧主操作或单独放在下一行；
- 更多操作按钮固定在最右侧；
- 避免三个文字按钮挤压在同一行。

### Library 验收标准

- 列表整体看起来是一个产品模块，而不是多张临时卡片；
- 用户能快速区分歌曲名称、元数据和当前状态；
- `Practice` 是视觉上最明确的操作；
- Export 和 Delete 不再与 Practice 争夺注意力；
- 当前歌曲在默认、悬停和滚动状态下都容易识别；
- 桌面端没有不必要的大块空白；
- 移动端操作不发生横向溢出；
- 键盘和屏幕阅读器仍能访问所有歌曲操作。

## 6. 暂不纳入本轮

- 新增封面、音乐图标或缩略图素材；
- 修改渐变背景本身的颜色和方向；
- 修改导航的信息架构或文案。
