# Piano Shadow 单页面识别与陪练计划

状态：已确认，作为后续 UI 与交互实现的产品基线

## 1. 产品决定

Piano Shadow 不再以“多页面 MIDI 练习工作台”为主要形态，而是收敛为一个单页面钢琴识别与陪练工具。

核心循环：

```text
Listen 监听外部演奏
    ↓
琴键实时跳动并识别音符
    ↓
Stop 停止识别
    ↓
将识别结果转换为 MIDI 曲目
    ↓
在下方曲目列表中保存、导出、删除或练习
```

核心产品对象只有三个：

1. 一排钢琴键：展示当前识别到的音符。
2. 识别控制：开始监听、停止监听、显示识别状态。
3. MIDI 曲目列表：保存识别结果，并提供练习、导出、删除操作。

## 2. 页面结构

页面保持单页，不使用首页、练习页、结果页之间的主导航跳转。

```text
┌──────────────────────────────────────────────┐
│ Piano Shadow                              设置 │
├──────────────────────────────────────────────┤
│                                              │
│                 [ Listen ]                    │
│             未开始监听 / 正在监听             │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │              88 键钢琴键盘              │  │
│  │       被识别到的琴键实时发光、跳动       │  │
│  └────────────────────────────────────────┘  │
│                                              │
│       识别时间线                 [ Stop ]     │
│                                              │
│ 我的 MIDI 曲目                    [导入 MIDI] │
│ ┌────────────────────────────────────────┐  │
│ │ 新录音  ·  1:24   [练习] [导出] [删除]   │  │
│ │ 我的旋律 ·  0:56   [练习] [导出] [删除]   │  │
│ └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

### 2.1 顶部区域

- 左侧只显示 `Piano Shadow` 品牌。
- 右侧只保留设置入口。
- 不显示 `Practice / Results / Lab` 主导航。
- Demo 曲目不再出现在页面中。
- 实验功能、调试面板和输入设备高级设置进入设置菜单。

### 2.2 监听控制

监听按钮是页面唯一的主操作，必须拥有最高视觉优先级。

| 状态 | 主按钮 | 辅助信息 |
| --- | --- | --- |
| 空闲 | `Listen` | 等待外部输入 |
| 初始化 | 禁用 | `正在准备麦克风…` |
| 监听中 | `Stop` | 红色录音点、`Listening…` |
| 已停止 | `Listen` | 显示刚刚生成的曲目 |
| 识别失败 | `Listen` | 明确说明原因并允许重试 |

监听过程中不要求用户先选择模式、曲目或录音设备。默认使用麦克风；如果麦克风不可用，应直接显示原因，并提供 MIDI 输入作为替代方式。

### 2.3 钢琴键盘

- 页面中央展示一排钢琴键，默认覆盖 A0–C8。
- 外部输入识别到音符时，对应琴键立即高亮或跳动。
- 识别中的键盘反馈是主要视觉反馈，不显示复杂 Piano Roll。
- 在使用实体钢琴或 MIDI 键盘时，键盘主要用于反馈；虚拟键盘输入可以保留，但不应抢占主视觉。
- 移动端或窄屏允许横向滚动键盘，但页面整体不产生横向滚动。

### 2.4 识别时间线

监听中显示简洁的音符事件时间线，用于让用户确认系统正在工作。

- 只显示音符事件、当前时长和识别进度。
- 不显示调试信息、置信度表格或完整 Piano Roll。
- 停止后时间线保留为本次识别的预览。

### 2.5 MIDI 曲目列表

列表是页面下半部分唯一的内容区。

每一行至少包含：

- 曲目名称。
- 新建标记或来源标记。
- 时长和音符数量。
- `练习` 主操作。
- `导出` 次操作。
- `删除` 危险操作。

新识别结果自动插入列表顶部，并获得 `New` 标记。默认名称可使用“未命名演奏 + 时间”，后续可增加重命名功能。

`导入 MIDI` 作为列表标题右侧的次级按钮，不再作为首页主入口。导入后直接在列表中生成曲目。

## 3. 陪练交互

点击某个曲目的 `练习` 后，页面仍停留在单页中，进入陪练状态，不跳转到独立 Results 页面。

陪练状态只显示必要信息：

- 当前曲目名称。
- 当前应弹音符或当前小节。
- 简洁的播放/暂停控制。
- 当前练习反馈，例如“正确”“弹早了”“弹晚了”。
- 退出陪练，返回 MIDI 列表。

`Listen / Play Along / Wait` 不作为主页面的三个并列标签显示。陪练方式收进“练习设置”，对用户使用更容易理解的名称：

- `跟拍`：应用按固定节奏播放，用户跟随演奏。
- `跟随`：应用等待用户弹奏后继续。

Tempo、节拍器、预备拍、输入设备等高级选项默认收起。

练习完成后，在当前页面显示简短结果卡片，并提供：

- 再练一次。
- 返回曲目列表。
- 查看详细结果（后续版本再实现，不作为首版主流程）。

## 4. 识别能力范围

识别是产品第一入口，但必须明确当前能力边界：

- 首版优先支持麦克风识别单音旋律。
- 和弦、多声部和高复杂度演奏优先使用 MIDI 输入或 MIDI 导入。
- 识别失败时必须允许重新监听，不得静默生成错误曲目。
- 识别结果统一转换为现有 `Performance` / `NoteEvent[]` 数据结构，再保存为 MIDI 曲目。
- 识别、MIDI 导入和后续练习必须共用同一套曲目列表与持久化逻辑。

## 5. 技术实施计划

### P0：单页面外壳

- 重构 `PracticePage` 为单页面容器。
- 移除 Demo 区域和主导航中的 Results、Lab。
- 保留设置菜单入口。
- 将曲目列表提升为页面核心内容。
- 让 `Practice` 成为当前页面内的状态，而不是主要路由跳转。

### P1：监听与识别主流程

- 从 `MicrophoneLabPage` 提取可复用的麦克风采集和识别逻辑。
- 将识别结果接入正式的输入适配层。
- 增加监听开始、停止、初始化、失败和重试状态。
- 识别过程中驱动钢琴键高亮。
- 停止后生成并保存新的 `Performance` / MIDI 曲目。

### P2：曲目列表操作

- 显示识别和导入得到的所有 MIDI 曲目。
- 增加导出 MIDI 功能。
- 增加删除确认和删除后的空状态。
- 新识别曲目自动置顶并显示新建状态。
- 复用现有持久化服务，避免产生第二套曲目数据模型。

### P3：单页陪练状态

- 在曲目行内提供 `练习` 按钮。
- 把 Play 和 Start Attempt 合并为“开始陪练”。
- 将陪练设置收进抽屉或弹出面板。
- 保留现有播放时钟、评分、Wait 行为和输入适配器。
- 陪练结束后在当前页面显示简短结果。

### P4：视觉与可用性验证

- 删除默认显示的 StatusStrip、Live Feedback 列表和完整 Piano Roll。
- 保留详细反馈作为可选展开内容。
- 统一按钮层级：主按钮、次按钮、危险按钮。
- 验证桌面端、窄屏、麦克风拒绝、无 MIDI 设备和空列表状态。
- 验证识别结果、导入结果和练习结果都能正确持久化。

## 7. 验收标准

首版完成必须满足：

- 打开应用即可看到钢琴键盘和 `Listen`，不需要进入其他页面。
- 点击 `Listen` 后，外部演奏能够驱动对应琴键实时反馈。
- 点击 `Stop` 后，识别结果自动生成 MIDI 曲目并出现在列表顶部。
- 曲目可以练习、导出和删除。
- 可以通过 `Import MIDI` 将 MIDI 加入同一列表。
- 没有 Demo 曲目，也没有复杂的主导航。
- 练习入口直接位于每一首 MIDI 曲目上。
- 麦克风不可用或识别失败时，用户能看到原因并重新尝试或改用 MIDI。
- 现有播放时钟、评分和输入适配器测试不回归。
- 页面在没有任何曲目时仍然清晰，监听入口不能被空状态遮挡。

## 8. 明确不纳入首版

- Demo 曲目和示例曲库。
- 独立 Results 页面作为主流程。
- 独立 Lab 页面作为用户功能入口。
- 默认显示完整 Piano Roll。
- 默认显示调试信息、详细置信度表格和复杂实时反馈列表。
- 麦克风多声部和弦识别。
- 多曲目文件夹、标签、搜索和云同步。
- 复杂的课程系统或教师端功能。

## 9. 成功判断

用户第一次打开页面后，应该能在几秒内理解：

1. 这里可以听我弹琴。
2. 被识别到的音符会在琴键上显示。
3. 停止后会生成一首 MIDI。
4. 我可以在下面直接练习这首 MIDI。

如果用户需要阅读说明、寻找 Demo、切换多个页面或理解内部模式名称，说明界面仍然过于复杂。
